# JVL Inventory — ระบบบริหารเวชภัณฑ์

ระบบบริหารเวชภัณฑ์ครบวงจรของ โรงพยาบาลจิตเวชเลยราชนครินทร์ ใช้ผ่านเว็บเบราว์เซอร์
ครอบคลุม **คลังยาใหญ่ (MAIN)**, **คลังยาย่อย OPD**, **คลังยาย่อย IPD** และ **คลังเวชภัณฑ์มิใช่ยา**

- Frontend: ไฟล์เดียว `Index.html` (Vue 3 แบบ Options API, Bootstrap 5, Chart.js, TomSelect, SheetJS)
- Backend: ไฟล์เดียว `api.php` (PHP + PDO + MySQL)
- ไม่มีขั้นตอน build — อัปโหลด 2 ไฟล์ขึ้นเซิร์ฟเวอร์ก็ใช้งานได้

## โครงสร้างไฟล์

| ไฟล์ | หน้าที่ |
|---|---|
| `Index.html` | หน้าเว็บทั้งหมด (UI, logic, แบบฟอร์มพิมพ์ F-SP-011 และใบ PO) |
| `api.php` | API ทุก action (รับ JSON `{action, data}` ตอบ `{status, data/message}`) |
| `../../db_config.php` | ตั้งค่าฐานข้อมูล (`$host`, `$db_name`, `$username`, `$password`) วางไว้**เหนือ** httpdocs ไม่อยู่ในชุดนี้ |
| `JVL_Inventory_Manual.pdf` | คู่มือผู้ใช้ |

## ติดตั้ง / อัปเดต

1. สำรองฐานข้อมูลก่อนทุกครั้ง
2. อัปโหลด `Index.html` และ `api.php` ทับของเดิม (โฟลเดอร์ `jvl_inventory`)
3. เปิดระบบ ตารางเสริมและคอลัมน์ใหม่จะถูกสร้าง/เพิ่มให้อัตโนมัติ (`CREATE TABLE IF NOT EXISTS` / `ALTER`) ไม่ต้องรัน SQL เอง:
   `product_barcodes`, `activity_logs`, `purchase_plans`, `purchase_orders`, `doc_evidence`, `units`, คอลัมน์ `products.ven`, คอลัมน์ role ของผู้ใช้
4. ถ้าแก้ที่อยู่ API ให้แก้ค่าคงที่ URL ใน `Index.html` (ปัจจุบันชี้ `https://chessyok.com/jvl_inventory/api.php`)

## ฟีเจอร์หลัก

- **รับเข้า/จ่ายออก**: บันทึกบิลบริษัท (รอตรวจรับ → ตรวจรับเข้าคลัง), จ่ายยา, ใบขอเบิก, ยิงบาร์โค้ด, Lot/Exp (เลือกเดือน/ปี)
- **คลังย่อย**: ขอเบิกจากคลังใหญ่, รับยาเข้าคลังย่อย, แสดงยอดและ Min/Max แยกคลัง
  - การตัดสต็อกในคลัง OPD/IPD ค่าเริ่มต้นคือ **จ่ายขึ้น Shelf** (ไม่ต้องกรอกเลขเอกสาร/ปลายทาง ระบบรันเลข `SHF-yyyymmdd-hhmmss` และบันทึกปลายทางเป็น `Shelf (OPD|IPD)`) Stock Card แสดงคำว่า "จ่ายขึ้น Shelf" · ประวัติรับจ่ายของคลังย่อยซ่อนรายการจ่ายขึ้น Shelf เป็นค่าเริ่มต้น (ติ๊ก "แสดงรายการจ่ายขึ้น Shelf" เพื่อดู เก็บใน localStorage) และมีรายงานสรุป "7. สรุปการจ่ายขึ้น Shelf" (ตามรายการยา/รายเดือน กรองช่วงเวลา) ใน สรุปรายงาน ของ OPD/IPD
- **ใบเบิก/ส่งคืน F-SP-011**: พิมพ์ได้ ใบที่คลังใหญ่ทำและมีรายการจากคลังย่อยปนอยู่จะแสดงเป็นใบเดียวในประวัติของคลังใหญ่ และพิมพ์เป็นใบเดียว รวมมูลค่า (รายการจาก OPD ขึ้น "น" ในช่องหมายเลขพัสดุ)
  - ช่อง "หลักฐานที่ใช้เบิก / ส่งคืน" (เลขที่เอกสาร + ลงวันที่ ไม่บังคับ) กรอกได้ตอนจ่ายยา หรือตอนกดพิมพ์ (มี pop-up ถามถ้ายังว่าง) เก็บในตาราง `doc_evidence` ผูกกับเลขที่ใบเบิก แก้ไขภายหลังได้จากหน้าต่างรายละเอียดเอกสาร
- **ใบ PO (คลังใหญ่)**: สร้างแบบ Auto (จาก Min/Max) หรือ Manual, ตั้งเลขที่ PO, พิมพ์ฟอร์มราชการแนวนอน A4, แก้ไข/ลบ
- **ตรวจรับ**: แก้ไข/ลบรายการรอตรวจรับได้ที่หน้าตรวจรับเข้าคลัง
- **ประวัติรับจ่าย**: แก้ไข/ลบรายการและหัวเอกสาร (ผู้ดูแลระบบ) ทุกการแก้/ลบบันทึก Log
- **Min/Max อัตโนมัติ**: คำนวณจากยอดใช้ย้อนหลัง N เดือน ค่าเริ่มต้นคลังใหญ่ Min 2 / Max 3 เดือน, คลังย่อย Min 1.5 / Max 2 เดือน (ปรับได้ เก็บใน localStorage ของเบราว์เซอร์) แล้วกด Apply ทีละรายการหรือทั้งหมด
- **สรุปรายงาน**: 6 รายงาน (+ รายงานที่ 7 จ่ายขึ้น Shelf เฉพาะ OPD/IPD) รวม **ABC-VEN Matrix** และ **สจ.รง.1051** (เฉพาะคลังใหญ่)
  - ABC คำนวณอัตโนมัติรายปีงบ (1 ต.ค.–30 ก.ย., พ.ศ.) แยกยา/มิใช่ยา เกณฑ์ A ≤ 80%, B ≤ 95% (ปรับได้) เลือกฐานมูลค่าได้: *จัดซื้อปีงบนี้* หรือ *ยอดยกมา + จัดซื้อปีงบนี้*
  - VEN กรอกเองในหน้าแก้ไขสินค้า (เฉพาะประเภท "ยา")
  - Dashboard มี Matrix ย่อ คลิกช่องเพื่อเข้ารายการ
- **รายงาน สจ.รง.1051 + Run/Control Chart** (คลังใหญ่): รายงานรายเดือนตามแบบฟอร์มกรมสุขภาพจิต (1. ผลการจัดซื้อ: ED/NED/มิใช่ยา × เงินงบประมาณ/เงินบำรุง + รวมแต่ต้นปีงบ, 2. เวชภัณฑ์คงคลัง: ยกมา/จัดซื้อ/รายจ่าย/ยกไป) พิมพ์และส่งออก Excel ได้ และการ์ด "แนวโน้มรายเดือน" บน Dashboard (เลือกช่วงเดือนได้, Run Chart = มัธยฐาน + ตรวจ shift 6 จุด, Control Chart = I-Chart ค่าเฉลี่ย ± 2.66·MR̄)
  - จัดซื้อ = IN ของบิลที่ตรวจรับแล้ว แบ่งตามยอดเงินบำรุง/งบประมาณของบิล (งบยาเสพติดนับเป็นงบประมาณ) · รายจ่าย = OUT ของคลังใหญ่ ไม่รวม lot `ADJUST` · ยอดยกมา/ยกไป = Σรับ − Σจ่าย (มูลค่าตามบันทึก) ของคลังใหญ่ ณ สิ้นเดือน โดยมีแถว "รายการปรับปรุงอื่น ๆ" เมื่อมีนับสต็อก/ปรับมูลค่า/รับเข้านอกบิล
- **แผนจัดซื้อประจำปี**, **ตรวจนับสต็อก/ปรับมูลค่า**, **ปรับรหัสสินค้า/ผู้ขาย/หน่วยงาน (ID migration)**, **ตั้งค่าระบบรวม** (สินค้า, ผู้ขาย, หน่วยงาน, ผู้ใช้, หน่วยนับ)

## บทบาทผู้ใช้

| Role | สิทธิ์ |
|---|---|
| `Admin` | จัดการทุกคลัง ตั้งค่าระบบ แก้ไข/ลบประวัติ |
| `User:<คลัง,...>` | ใช้งานเฉพาะคลังที่ระบุ (เช่น `User:OPD`) ผู้ที่มีสิทธิ์ MAIN ทำใบ PO ได้ |
| `God` | บทบาทผู้พัฒนา (ไม่ระบุในคู่มือผู้ใช้): ดู Log ทั้งหมด และ **กู้คืนรายการ/ใบที่ถูกลบ** จากหน้า Log |

> หมายเหตุ: การตรวจสิทธิ์ฝั่งเซิร์ฟเวอร์ทำจาก `username` ที่ส่งมากับคำขอ ยังไม่มีระบบ token/session จริง
> ควรใช้ภายในเครือข่ายโรงพยาบาลหรือเพิ่มระบบยืนยันตัวตนก่อนเปิดสู่อินเทอร์เน็ตกว้าง

## Log และการกู้คืน

- ทุกการแก้ไข/ลบ/Apply/PO/ขอเบิกบันทึกใน `activity_logs` (ถ้าเขียน Log ไม่สำเร็จ การกระทำนั้นจะถูกยกเลิก)
- Log การลบ (`DELETE_ITEM`, `DELETE_DOC`) เก็บแถว `transactions` เต็มรูปแบบ (และหัวบิลถ้าลบทั้งบิล) เพื่อให้ God กู้คืนได้ด้วย action `restoreDeleted`
  - ใบเดียวกันที่ถูกลบแยกหลายคลังจะกู้คืนพร้อมกัน (ผู้ทำคนเดียวกัน ห่างกันไม่เกิน 30 นาที)
  - กู้ซ้ำไม่ได้ และจะไม่ยอมใส่ถ้ารหัสรายการ (`trans_id`) มีอยู่แล้ว
  - Log เก่าที่ไม่มีข้อมูลเต็มกู้ไม่ได้

## API (`api.php`)

POST JSON `{ "action": "...", "data": { ... } }` — ส่ง `username` สำหรับ action ที่ตรวจสิทธิ์

| กลุ่ม | Action |
|---|---|
| ทั่วไป | `testConnection`, `getData`, `getNextId`, `saveUnit`, `registerUser` |
| ข้อมูลหลัก | `saveMasterData`, `deleteMasterData`, `saveBarcode`, `deleteBarcode`, `migrateIds` |
| รับ/จ่าย | `savePendingBill`, `approveBill`, `saveBatchTransaction`, `saveSubReceive`, `saveStockTake`, `saveValueAdjustment`, `clearEmergency` |
| ขอเบิก | `saveRequest`, `updateRequest`, `deleteRequest`, `updateRequestStatus`, `updateToActualReq` |
| PO | `savePO`, `deletePO` |
| Min/Max | `saveStockLevel`, `saveStockLevels` |
| แก้ไข/ลบประวัติ | `updateTransactionItem`, `updateDocHeader`, `deleteTransactionItems` |
| แผนจัดซื้อ | `savePurchasePlan`, `deletePurchasePlan` |
| หลักฐานใบเบิก | `saveDocEvidence` |
| Log (God) | `getActivityLogs`, `restoreDeleted` |

## ข้อควรรู้ / ข้อจำกัด

- ค่าตัวคูณ Min/Max, เกณฑ์ ABC, ฐานมูลค่า ABC, ลายเซ็นใบ PO เก็บใน localStorage ของแต่ละเบราว์เซอร์/เครื่อง
- ABC ใช้มูลค่าจากบิลที่ตรวจรับแล้ว (และยอดยกมาเมื่อเลือกฐานนั้น)
- ชุดทดสอบที่ใช้พัฒนาเป็นการทดสอบหน้าเว็บกับ API จำลอง ยังไม่ได้ทดสอบอัตโนมัติกับ MySQL จริง — ควรสำรองข้อมูลก่อนอัปเดตทุกครั้ง
